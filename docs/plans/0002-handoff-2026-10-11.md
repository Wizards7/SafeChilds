## How to run locally

```
pnpm db:up                                              # Postgres :5434
DATABASE_URL=postgres://safechilds:safechilds@localhost:5434/safechilds pnpm --filter @safechilds/db migrate
DATABASE_URL=postgres://safechilds:safechilds@localhost:5434/safechilds pnpm --filter @safechilds/db seed
cd apps/backend && DATABASE_URL=... PORT=4100 CORS_ORIGINS=http://localhost:3000 pnpm dev
cd apps/mobile  && NEXT_PUBLIC_API_URL=http://localhost:4100 NEXT_PUBLIC_APP_URL=http://localhost:3000 pnpm dev
pnpm typecheck && pnpm test
```

Known environment quirks: the Claude desktop preview sandbox cannot `cd` into `~/Documents` and cannot run service workers — start servers from Bash and open `localhost` in the Browser pane; verify the service worker on the Railway URL. Next dev once cached a 404 for a route created while it was running — restart dev if a new route 404s. `pnpm` is on PATH via corepack at `~/.npm-global/bin/pnpm`.

## Decisions taken during the build (all recorded in 0001)

Plain CSS from the sketches, no Tailwind · `POST /analysis` multipart instead of a tRPC procedure · `c2pa` presence-only (`c2pa_present_unverified`), validation at pilot · hand-written service worker instead of `@serwist/next` (Turbopack) · Russian month names for dates in both languages (no Tajik `Intl` locale in browsers) · CRM deferred, seeds carry directory + helplines · demo image = a team member's own photo.
